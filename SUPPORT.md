# Support

## Before asking for help

Check:

1. [`README.md`](README.md)
2. [`docs/GETTING_STARTED.md`](docs/GETTING_STARTED.md)
3. [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md)
4. open GitHub issues
5. [`docs/FEATURE_PARITY_MATRIX.md`](docs/FEATURE_PARITY_MATRIX.md)

A desktop feature may simply not have reached Android parity yet.

## Bug reports

Use the GitHub bug-report issue form.

Include:

- commit/version;
- Android version / API level;
- device or emulator;
- JDK/Gradle versions for build failures;
- exact reproduction steps;
- expected and actual behavior;
- relevant sanitized logs.

Never include real API keys, authorization headers, private prompts or personal data.

## Feature requests

Use the feature-request template and explain:

- problem being solved;
- expected user behavior;
- whether Venice Forge desktop already implements it;
- relevant API capability if known.

## Security

Do not use normal support channels for exploitable vulnerabilities. Follow [`SECURITY.md`](SECURITY.md).

## Provider/API incidents

If the failure appears provider-side, capture:

- endpoint name;
- model ID;
- HTTP status;
- request ID if safely available;
- timestamp;
- sanitized error body.

Do not publish authentication material.

## No guaranteed SLA

This is an open-source project under active development. Support availability and response time are not guaranteed.
